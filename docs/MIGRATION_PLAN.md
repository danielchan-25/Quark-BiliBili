## 3. Linux 运行设计

1. 代码和虚拟环境位于普通用户可写目录；目标机新建 `.venv`，不复制 Windows 的 `.venv`。
2. SQLite 默认保留项目内 `data/` 布局，方便一致性迁移。日志为 UTF-8 JSONL；文件权限限制到运行用户。
3. 业务发布时间显式使用北京时间；SQLite `CURRENT_TIMESTAMP` 的 UTC 任务时间保持原有语义，迁移不重写历史时间。
4. Linux 准备子进程建立独立进程组，超时只清理该组内的准备进程和 Playwright 驱动；用户管理的 Chrome 不属于此组。
5. ChromeManager-Linux 正式部署启用 relay；使用两个固定公开端口的 `http://127.0.0.1:端口`。账号 CSV、数据库登记和实际 UID 必须一致。
6. 本地计划配置从 Git 排除，仓库只含虚构示例；所有计划仍按 `Asia/Shanghai` 解释。

## 4. 定时与文案编排

优先延续已有智能调度：两个账号的发布计划，以及一个北京时间 23:55 的合并日报计划。新环境必须重新设置项目工作目录、`.venv/bin/python` 和本地计划配置路径。

每轮流程：

1. 按触发时刻选择本次应执行的完整 `--slot`（带 `+08:00`），不补跑旧轮次。
2. 调用 `tools/scheduled_promotion.py --account ... --slot ... --phase prepare`。
3. `already_exists`、`already_running`、`stopped` 时停止；只有 `ready` 才继续。
4. `phrase_ready=false` 时，根据当轮返回的视频主题和资源类别写一条真实文案 JSON，保留唯一 `{url}`；禁止编造内容或使用体验。
5. 调用同一账号和同一时段的 `--phase publish`，需要时传 `--phrase-file`。候选改变时按新候选重新准备文案。
6. 外部准备异常通过同轮 `--phase stop` 收尾；发布接受或结果未知后只读核验，不自动重发。停止轮次的 `--resume` 仍需要人的明确授权。

Python 项目内的 `AI_API_*` 配置不代表已实现文案生成。单独用 cron 调用一次 prepare 不会完成发布；本阶段不默默引入新的模型供应商或计费服务。独立于智能代理的系统定时只用于已有纯 Python 日报等明确操作，安装时默认不启用。

## 5. 业务数据迁移清单

必须一致迁移：

- `data/mediaflow.db`：账号、资源、候选、文案、历史视频、发布预留、发布与任务记录；包含结果不明的提交。
- `data/account.csv` 与 `.env`：由部署者通过受控文件传输恢复，不进入 Git。
- `data/scheduled-runs/`，含该目录下的通知回执。
- `data/notification-receipts/`、`data/daily-reports/`、`data/promotion-schedules/`。
- 可选保留 `data/typesafe-cache.db`、`data/candidate-pool/maintenance.json` 与审计日志，以减少重复审核并保留证据。

不直接迁移：Windows 虚拟环境、浏览器 Profile、Cookie、旧 PID、浏览器会话 WebSocket UUID、文件锁和 `.tmp` 中间文件。锁只允许在确认相关进程已退出后处理，不得删除业务 reservations、轮次 JSON 或未知通知回执。

迁移备份本身包含私有运营数据，必须保存到仓库外的受限目录；备份工具不得打印正文、链接或密钥。SQLite 使用 backup API 创建快照，归档清单记录校验值；恢复前先验证全部文件，目标存在时拒绝覆盖。

## 6. 切换与回滚

1. 固化当前源码版本；先暂停旧机两个发布计划和日报计划。
2. 等待已启动的发布结束。对 `submitted`、`submission_started`、`publishing`、`requires_readonly_recheck` 和通知 `sending/unknown` 逐项只读核对；不得当成未发生而重跑。
3. 确认停写后生成业务状态备份并核对清单，保留原机器和浏览器作为回退环境。
4. Ubuntu 在定时任务关闭的状态恢复数据。端点改变时同步 CSV 和数据库；保留原账号身份和计划启用时间。
5. 完成只读验收，再安排两个账号各一次单条发布验收；未知结果不重试。
6. 只启用 Ubuntu 计划，旧机保持关闭。停机期间的历史时段不补发。
7. 需要回滚时先停 Ubuntu 计划，等待或核对在途操作，将迁移后新增的完整业务状态带回旧机后再启用旧机。不得回到旧快照而忘记新发布与预留。
